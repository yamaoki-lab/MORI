# macOSでの開発用セットアップ

macOS Sequoia (このマシンで実機確認したのはmacOS 15.7.7) は, `networksetup`/`scutil`/`system_profiler`/`wdutil`のいずれを使っても, SSIDの読み取りだけを一律で伏字化する (電波強度・チャンネル・規格・セキュリティ方式等, SSID以外の情報は無権限のまま取得できる). 位置情報の権限を与えても, sudoで実行しても変わらない. 唯一, 正規のApple製アプリであるショートカット.app経由でのみ実際のSSIDを取得できる.

そのため, `wifi`パッケージのmacOS実装 (`manager_darwin.go`) は, 以下の手順で作成したショートカットに依存する. このセットアップをしていないマシンでは, `CurrentNetwork`/`ListNetworks`が常に "未接続" を返す (エラーにはならないが, SSIDが取得できない).

## セットアップ手順

1. ショートカット.appを開き, 新規ショートカットを作成する
2. 名前を "ネットワーク名を取得" にする (`wifi`パッケージがこの名前で呼び出す. 変える場合は`shortcutoutput.go`の`shortcutName`も合わせて変更する)
3. アクション "Wi-Fiネットワークの ネットワーク名 を取得" を追加する
4. 続けてアクション "シェルスクリプトを実行" を追加し, 以下の設定にする
   - シェル: `zsh`
   - 入力: 直前の結果 ("ネットワークの詳細")
   - 入力を渡す方法: `stdinへ`
   - スクリプト内容:
     ```
     tee /tmp/mori_current_ssid.txt | say
     ```
     (`say`で読み上げる部分は無くても動作する. `/tmp/mori_current_ssid.txt`への書き出しが本質)

## なぜ`shortcuts run`の戻り値ではなくファイル書き出しなのか

ショートカット末尾に "停止して出力" を置いて`shortcuts run "ネットワーク名を取得"`を実行しても, 呼び出し元のターミナルの標準出力には何も出ない (シェルスクリプトアクション自体はSSIDを正しく扱えており, ショートカット.app側のプレビューでは値が見える). これは意図的な遮断というより, シェルスクリプトアクションの実行結果がショートカット側で完結しており, `shortcuts run`を叩いたプロセスの標準出力へは経路として繋がっていない, という理解 (実行される場所が違う). そのため, 経路に依存しない受け渡し方法として, シェルスクリプトアクション自身にファイルへ直接書き出させている.
